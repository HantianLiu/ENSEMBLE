# Project_ENSEMBLE v0.7.5

[中文说明](README_v071.md) · [English guide](README_v071.en.md)

这是供公开反馈的早期预览版，不是稳定的无人值守研究服务。模型生成的科学陈述、
引文对应和最终报告仍需使用者核对；请不要把未核验报告直接用于高风险决策。
欢迎通过 GitHub Issues 的缺陷或研究体验模板反馈，最好使用合成任务、最小复现
步骤及去标识化截图。不要上传真实会议目录、证据包、API 密钥或私人研究材料。

这是基于 v0.7.1 文献写作治理规则的 **0.7.5 软件发行版**，与旧版独立并存。它安装主命令
`ensemble`；旧版本改用 `ensemble-old`。两个版本使用独立虚拟环境，不就地升级旧会议。

本项目代码和项目文档按 [MIT 许可证](LICENSE)分发；随附字体不在该许可范围内。

PDF 默认使用随程序打包的 HarmonyOS Sans SC：一款可免费商用的全场景字体，
提供 Regular、Medium、Bold 字重。字体仍须遵循其独立许可，不受本项目许可证覆盖；
完整许可随字体文件分发，详见 [第三方资源声明](THIRD_PARTY_NOTICES.md)。

HTML 是默认的富文本阅读格式：一个文件可在有浏览器的系统中直接打开，体积小，
又能提供章节目录、可收放的术语/引文侧栏、表格横向滚动、数学排版、高亮、批注和
读者自备 DeepSeek API key 的可选问答。文献报告从同一份冻结 Markdown 分别生成
HTML 与 PDF；Markdown 仍是可编辑、可核对的底稿。PDF 继续生成，学术重绘中的
PDF/LaTeX 仍可按需选择；HTML 是优先打开的阅读版。
点击引文目前展示的是参考文献
条目，**不是**逐句原文证据摘录。若 PDF 排版失败，已完成的 Markdown 和 HTML 仍留在
`public/final/`，会议不会错误地标记为出版完成；恢复时可继续修复 PDF。HTML 数学公式
目前通过 MathJax 的 HTTPS 资源加载，离线打开时公式会保留可读的 TeX 表述，尚未提供
完全离线的公式资产包。PDF 仍使用 ReportLab 排版；对于少数复杂 TeX 结构，应以冻结
Markdown 核对，不应把 PDF 的视觉呈现当作数学正确性的独立证明。

HTML 中选中正文会出现“高亮／批注／问 AI”工具条。标注默认保存在本机浏览器；
目录与“批注和问答”列表使用并列标签，“问 AI”入口位于后者内部；搜索框（Ctrl/Cmd+F）会在右侧文档位置条标记匹配处。
“批注和问答”是单行条目目录：批注显示摘要，问答仅显示问题，不在目录里展开答案。桌面端两种目录共用正文左侧的一栏，利用左边空白向左加宽，不侵入正文；切换标签时宽度与正文位置均不变。条目之间使用浅色横线，每条仅保留删除按钮。点击条目在右侧展开完整内容，保留 Markdown、表格与公式排版；问答全文可继续问 AI，并与问答窗口等宽并列。
页面为纯白背景，正文和右侧全文／问答面板为带阴影的不透明白色纸带。已保存批注默认显示随原文滚动的半透明毛玻璃浮窗，使用静态密集随机浅颗粒与较强阴影；浮窗及问答窗口中的回答仅预览约五行，全文在右侧展开，存储内容不截断。浮窗不挤窄正文、不重复原文；双击内容可编辑。纯高亮不打开浮窗，也不出现在目录中（关联问答仍显示）。重叠卡片默认以原文锚点接近页面中线者置顶，选中卡片优先置顶，带轻量过渡。
“编辑／问 AI／删除”竖排在浮窗右侧，仅在点击该浮窗后出现，不另设“定位”按钮。系统“减少动效／透明度”偏好优先生效。位置参考条始终位于所有面板最右侧。
浮窗操作区、批注编辑窗口和全文窗口中的 ☆／★ 可切换“重要批注”。加星后目录条目以星号和加粗文字突出显示；右侧另设独立的星标列，与最右侧的位置／搜索条分开。星标使用较大的深灰实心五角星、白色描边和阴影，点击可直接定位原文；普通位置标记仍保留在位置条内。浮窗、操作按钮和右侧面板避开星标列，不改变正文布局。星标随本机保存、HTML／JSON 导出和导入保留，旧批注无需转换；纯高亮不显示重要批注星标。
左侧章节目录随正文滚动突出当前章节／小节，以加粗文字、浅色背景和左侧色条标识；长目录会在当前项移出可见区域时仅滚动目录内部，不移动正文。切换到“批注与问答”后仍跟踪章节位置，返回目录时显示当前项；点击目录或浏览器前进／后退导航后也会更新。打印隐藏位置与星标列。
左侧导航新增“聚焦模式”与配色选择。聚焦模式默认关闭；开启后，鼠标指向标注原文、只关联一条标注的段落或批注浮窗时临时聚焦，单击锁定，点击空白正文或按 Esc 解除锁定；没有主动聚焦时，以可见标注中最接近页面中线的批注为焦点。焦点原文加强高亮，其他文字降低饱和度但保留可读性；对应卡片通过位移、轻微缩放和分层阴影浮起，其余卡片轻微变灰。开启聚焦后单击标注只锁定，不自动弹出全文面板，双击仍可编辑；键盘聚焦卡片后 Enter／空格同样可以锁定。配色可在原有白色和“浅黄 · 奶油纸”之间切换，并同步至问 AI 窗口。外观偏好保存于浏览器，另存的带批注 HTML 也保留当前配色与开关；批注格式、正文存储键不变。打印不保留聚焦淡化，减少动画偏好下取消动效；暂不提供深色模式。
从高亮／批注问 AI 时两个等宽面板并列；直接问 AI 时只打开一个面板。面板均从右侧滑入、覆盖显示，不改变正文布局；点击正文即可收起。
圈选后右键不再弹出遮挡工具条的浏览器菜单；Shift+右键保留原生菜单。
Alt+Shift+H/N/A 分别用于高亮、批注、问 AI。纯高亮可双击进入批注编辑并删除；批注及关联问答也可从左侧删除。
也可另存为嵌入标注的 HTML 副本供分享。界面升级保留同一正文的批注数据格式与存储键；
本地文件换路径后若浏览器不共享存储，可在旧页面保存带批注 HTML，再在新版“导入数据／旧副本”。
也支持 JSON 导出／导入，同 ID 优先保留已有本机批注。旧版哈希不同时先核对会议与原段落，
仅展示变化可直接导入；不同正文版本只迁移仍未改变、能够准确定位的段落，并须确认。
旧 JSON 若缺少来源上下文，必须逐字、唯一匹配原文后由读者确认，不能确认或存在多处匹配时请改用旧版带批注 HTML。
读取进度与失败原因显示在导入按钮旁；原始 HTML 不包含本机浏览器里的批注，须先保存带批注副本。
问答支持表格与公式，可以追问并单独
保存到本机浏览器；API key 仅在当前打开的问答窗口内存中复用，不写入 HTML、批注
或问答历史。分享页面或屏幕前请主动清除密钥。问答与公式排版依赖外部服务或脚本，
只在信任报告来源时输入密钥；公式资源未加载时会保留原始 TeX。

主笔可用单行 `> **来源状态**：…` 或 `> **实现说明**：…` 保存次要说明。HTML 将这类
说明显示为小号 `[注]`，点击后在侧栏展开；PDF 保留原引用块。会改变科学结论范围的
限制仍须写在正文，不能只放入注释。Markdown 还支持 `[^note-id]` 与
`[^note-id]: 说明`；PDF 会将这种脚注转为编号尾注。

搬迁会议目录后，在新目录（或其父目录）运行 `ensemble`，选择“接续已有会议 → 从当前目录寻找”。
程序只检查当前目录及一级子目录中的会议标识；如果会议 ID 已在列表中但路径不同，会先询问
是否更新位置，也可仅本次打开；未登记的会议会加入列表。会议正文与冻结记录不会改写。
原始配置路径已失效时，恢复流程可使用会议内部通过哈希校验的配置快照。
也可在容纳多个会议的目录运行 `ensemble update`，一次将当前目录及一级子目录中的会议加入
列表或更新路径；此命令不需模型配置，不会修改会议文件。若发现多个相同会议 ID 的副本，
会跳过该 ID 并报告冲突，避免误登记。

运行 `ensemble gather`，可从**当前目录及一级子目录**发现的会议中多选。
只需两次选择：会议，以及要打包的 Markdown、HTML、PDF／文献 ZIP。
HTML/PDF 自动使用当前排版器，编号支持空格、中英文逗号和 `1-3` 范围。
默认输出 `会议资料.zip`；`ensemble gather --output /path/to/exports` 可指定目录，
也可指定 `--output /path/to/收集.zip`。同名输出保留原文件，新 ZIP 加“（2）”等后缀。
总 ZIP 内每场会议只有一个以会议名称命名的文件夹，里面仅放最终文本与可选的文献 ZIP，
不含随机目录名、会议 ID 后缀或清单 JSON；文献 ZIP 内直接放 PDF，没有子目录。
选择收集文献时，生成按会议名命名的文献 PDF ZIP，
包括本机已下载或人工提供的 PDF，并按内容哈希去重；不会补下载缺失文献。
只收集完整最终稿或最新完整勘误稿，不把未完成模块当成最终文本；
某场会议或某种格式失败时，已成功收集的文件仍保留，终端列明未收集的内容。
重新渲染不调用模型、不重开审阅、不改写冻结正文；无需模型供应商配置。

已完成的会议可在 `ensemble → 接续已有会议 → 从会议列表选择 → 补充排版格式` 中选择只补 HTML、只补
PDF，或两种都补。此操作不调用模型、不重开审阅，也不覆盖已发表文稿；它从最新完整的
会后勘误稿（如存在）或已完成的最终 Markdown 生成独立衍生文件。精简归档后的会议
同样可使用保留的完整文稿；程序会先核对归档哈希。成果在会议一级目录显示为
`SUPPLEMENTARY_REPORT.html` / `SUPPLEMENTARY_REPORT.pdf`，每种格式另存来源与输出哈希。
渲染缓存同时核对排版代码、阅读器资源与渲染输入；界面或公式处理更新后会生成新阅读版，
不会因为正文未变而继续复用旧界面，也不会覆盖已有冻结排版文件。
如果选择两种格式而 PDF 排版失败，已经成功生成的 HTML 仍可打开；会议的完成状态不变。

## 启动

需要 Python 3.12 或更高版本。在本目录执行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/ensemble
```

也可以直接调用 `scripts/ensemble`；它优先使用本目录的 `.venv`，否则
使用 `ENSEMBLE_PYTHON` 指定的 Python。`ensemble-v071` 仍作为兼容别名保留。
模型 API 密钥、OpenAlex/Tavily
等配置沿用同目录的 `ensemble.toml`/`model_config.toml` 结构。`ENSEMBLE_CONFIG`
可指向另一份配置。推荐在独立环境中安装，不要把本版本 `pip install -e .` 到
原有 v0.7.0 虚拟环境，因为二者的 Python import package 名相同。

首次进入 `ensemble` 时先选择中文或 English 界面，以后可在“设置 → 界面语言”修改。
此选择只影响菜单和运行进度标签；每场会议的成文语言独立选择，已有会议不随界面设置改变。
初始化页会解释会议形式、执行步骤与各角色的模型选择。议事会议也可先与主席对话，
共同形成完整任务委托，再由人类确认后正式建会；直接输入任务的方式仍然可用。

四种代表人格的代号——Builder、Monitor、Cartographer、Librarian——受 *Halo* 启发。
借用作者的玩笑话：*the greatest FPS game ever, to the best of the author's knowledge*。
这只是命名彩蛋，不代表与该游戏存在官方关联，也不改变各人格在会议中的职责。

## 新流程

### 议事会议适合做什么

议事会议用于把尚待确定的规则、任务要求、评价标准或高度约束的提示词委托，
形成一份有决策记录的规范性文书。来自不同模型的代表对条款分别提案、质疑、
修订和表决；主席按会议程序整合通过的内容，需要人类裁定的事项仍交给人类。
它的交付物是可审计的规则或委托文本，**不是**执行该委托后的研究结果，也不
默认检索文献、核实经验事实或生成综述。如果目标是回答一个事实问题，应选
「命题核实」；如果目标是完成有证据支撑的报告，应选「文献调研」。
「审计会议」的执行器尚未完成，因此暂不在新会议菜单中提供，也不能通过非交互
初始化创建；现有审计类型的落盘资料仍保留，等待后续版本支持。

现已提供独立的**轻量审计**：从首页选择「轻量审计已有会议」，或运行
`ensemble audit`。先从会议列表多选（支持空格、中文逗号及 `1-3` 范围），
再选择仅程序核验，或增加独立模型可读性审读。未归档且已完成的会议检查可用
投票、修订交付、公开科学复核和历史空转记录；已归档会议改为检查保留文件、
完整正文和引文，删除的流程记录明确标为「无法核验」。未完成会议不揭示密封票。
审计不修改原会议、不自动启动修订，也不替代完整审计会议认证。

输出保存在当前目录新建的 `ensemble_audit_…` 中，含汇总及各会议的
`AUDIT_REPORT.md`／`AUDIT_REPORT.json`。`private_inputs` 是私有来源快照，
不要作为公开报告上传。模型失败或安全中断不丢弃已有程序核验。
仅做无需模型配置的核验可运行 `ensemble audit --no-ai`；重复
`--meeting ID或路径` 可直接指定会议，`--output /path/to/audits` 设置输出父目录。
详细检查范围见 [轻量只读审计协议](docs/governance/05_audit_conference/lightweight_audit_protocol.md)。

初始化时既可直接输入完整委托，也可先与筹备主席对话形成委托。筹备对话只
帮助明确要制定的规则和交付标准，不等于已经召开议事会议。

### 文献调研

初始化时选择「文献调研」，再选「简易流程」或「完整流程」。简易流程不任命 Chair：选择一名贯穿全文的
学术主笔、Research Desk、两至三个仅负责模块拆分提议的模型，以及至少两个不同基础模型的智库长审阅者。开题时可直接输入
完整研究委托，也可与仅负责会前拟稿的筹备主席对话；两条路径均由模型根据最终委托拟定
可修改的会议标题。拆分提议模型各做一轮最多八条检索式的探索，并行提交独立方案；
主笔的新调用只接收匿名方案及检索线索，不知道各方案来自哪个模型，也不表决或机械拼接，
而是自行拟定模块任务书。用户硬约束不能改变；人类批准模块划分之前不开始正式证据核查。随后主笔逐模块制定执行计划，
每模块最多安排三轮可提前停止的查询；独立问题可由 Research Desk 并行核查。主笔按
章节顺序写作，智库长密封提交科学异议；修订稿须获智库长过半认可，否则暂停交人类
处理。引文与出版使用确定性校验，不进行主席终审，也不要求逐章人工批准。该模式的
流程标记在初始化时冻结为 `fast`；既有会议及下述普通 `v071` 写作流程不变。

非交互式初始化可使用 `--deliverable-type literature_review
--literature-writing-policy fast`，同时指定 `--writer-model`、至少两个不同的
`--model`、`--research-model`，并重复两至三次 `--fast-planner-model provider:model`；快速模式不提供 `--chair`。
既有快速会议若未冻结拆分提议模型，恢复时继续沿用旧的主笔单独规划流程。

新建文献报告会议时，除主席和 Research Desk 外，另选一位独立学术主笔的模型与
reasoning effort。模块研究与证据整理仍用既有机制；每个模块的 dossier 冻结后：

1. Builder 只提结构性写作提纲；非 Builder 三办公室按全票、再按 2/3、最后自动采纳的
   三稿机制确定提纲。
2. 同一位学术主笔顺序写各模块，逐章只接触本章证据、前章短摘要与滚动术语表。
3. 本会所有智库长密封、独立提交科学异议清单；主席逐条处置，打回异议可由无关智库长
   过半救济。主笔返修后再进行一轮科学清单，最终只核查改动段落。
4. 科学审阅结束后进行引文与出版组装。内部 `C00001-00001` 式临时来源 ID
   会在出版时按首次出现顺序改成读者引文。

新建文献报告会议的主笔输入还会包含按“具体发现—适用条件—局限—文献编号”组织的
事实优先索引，参考文献目录单独提供；完整 evidence dossier 仍保留供核查。
事实卡会标记写作时能够核对的材料层级（题录/摘要、网页检索摘录或本地文件摘录）。
Builder 先围绕问题和比较维度安排提纲；主笔必须先说判断、再说明关键证据与适用范围，
不得把来源清单改写成正文，也不能把摘要或检索片段冒充已核对全文的细节。
已经运行且没有冻结这一写作偏好的会议继续使用原有输入，不在恢复时偷偷替换材料。

交互式初始化可逐份输入本地参考资料路径，直接回车结束。支持 PDF、TXT、Markdown、
HTML 与 CSV；非交互模式可重复传入 `--human-reference PATH`。原文件按 SHA-256
复制到会议的 `public/human_references/`，可提取的文本作为 Research Desk 的候选来源
参与检索，并可进入可下载的会议文献包。上传并不意味着来源可靠或结论成立：仍须由
Research Desk 逐项核验。扫描版 PDF 若无法提取文字会保存原件，但暂不能全文检索；
目前每场会议最多导入 20 份、单份不超过 100 MiB，会议开始后不追加资料。

## 管理已有会议

直接运行 `ensemble`，选择“管理已有会议”，再从全局会议列表选择目标会议。
“精简归档”保留会议清单、原始任务、Research Desk 证据包、可下载文献包、
人类提供的参考资料，以及最终成稿；若原会尚未出版，则只在存在一份完整落盘的
整篇草稿时，才将它提升为后续会议可继承的文稿。单个模块或重绘章节不算整篇草稿。
如果主席修订后的整篇文本只保存在最终可读性审查记录中，系统须先核对冻结的
SHA-256 哈希，才会将这份较新的文本导出为归档文稿。
精简后，原会议的流程与审计原始记录被删除，不能继续原流程，但仍可从会议列表
选择它，继承证据或文稿召开新会。未通过原程序认证的草稿会被明确标注，
不会伪装成已认证结论。归档清单 `public/archive_manifest.json` 记录保留文件的
SHA-256 哈希、所选原文稿及来源认证状态。

文献 ZIP 是按需导出的副本，不再在研究过程中反复生成，也不长期保存在精简归档内。
文献原文件、来源清单和证据包仍保留；用 `ensemble gather` 可重新打包文献 PDF。
旧归档的 ZIP 清理先校验原归档及全部 ZIP 内容，独有文件或不同版本先完整保留，
再移除 ZIP；维护记录保存在 `public/archive_maintenance/literature_zip_retirement.json`，
原归档清单不改写，接续校验会核对这份维护记录与保留原文件。

“彻底删除”在输入带会议 ID 的确认词后启动后台任务，前台立即返回；
终端会显示位于用户设置目录 `deletions/` 下的状态 JSON 和日志路径。
状态从 `QUEUED` 到 `RUNNING`，最终为 `DONE` 或 `FAILED`；只有 `DONE`
表示目录已删完并从全局会议列表移除。若失败，状态记录保留残留目录路径。
精简和删除在 NFS 文件系统上都会先释放会议锁再清理旧目录，并对短暂的
“目录非空”错误重试。
会议正常结束时，交互终端也会询问是否精简归档；选择保留即可跳过，
暂停的会议不会收到这个询问。两种操作都建议事先备份；删除后 ENSEMBLE
不提供恢复功能。正在运行的会议不能归档或删除；先在原终端安全中断并等待退出。

途中模型输出和决定分别落为不可变文件，重启只恢复未完成步骤；既有会议在缺少
`literature_writing_policy = "v071"` 时保持旧流程。完整试行规则参见
[`docs/governance/02_deliberation/literature_writing_v071.md`](docs/governance/02_deliberation/literature_writing_v071.md)。

## 范围与验证

独立目录中的单元和回归测试可用 `python -m pytest` 运行。当前代码未对任何生产
文献会议做端到端实测；在大规模真实会议使用前，建议先召开一场小型、可中断的前台会议。

重审版本链。这些分支不会被暗中默认通过；现阶段遇到相关故障会停下，已冻结文件保留。
